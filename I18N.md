# Multilingual Tk application

Run `main.py`; its UI and `backup_manager.py` use the offline `i18n.py` catalogs.
Bundled locales: Arabic, English, Simplified Chinese, French, Spanish, Hindi and
Turkish. There are 129 messages per locale. This is extensible localization,
not a claim of translation into every world language.

Install with `python -m pip install -r requirements.txt`, then `python main.py`.
Windows needs Python with Tkinter (included by the python.org installer).
The first launch uses a supported system locale, falling back to English.
The language selector saves a per-user preference and applies it after restart.
`CDRIVE_CLEANER_LANGUAGE` overrides that preference. Settings live in
`%APPDATA%/CDriveCleaner/settings.json` on Windows, or
`$XDG_CONFIG_HOME/CDriveCleaner/settings.json` (default `~/.config`) on Linux.
`CDRIVE_CLEANER_SETTINGS` can select an alternative settings file for testing.

Add `locales/<code>.json`, using `en.json` as the template. Translate values,
retain keys and format placeholders (including format specifications), provide
a native `name` and `direction` of `ltr` or `rtl`, and save UTF-8. Catalogs are
discovered at launch. Missing or invalid entries fall back to English. Extra
writing systems need font coverage and platform rendering verification.

Arabic widget text is shaped and reordered at the presentation boundary using
arabic-reshaper and python-bidi. Native Windows dialogs receive logical Unicode.
Raw file paths, editable values, category IDs and selection data are preserved.
Horizontal controls and text anchors mirror for RTL; path fields keep natural
path ordering. Fonts are chosen from installed fonts with script coverage.
The original cleanup algorithms and safety defaults are unchanged.
Developer logs and operating system error text may remain in their original
language. Legacy `cleaner_ui.py` is an unused PyQt alternative and is not part
of this localized Tk launch workflow.

Run `python -m unittest discover -s tests -v`. The GUI smoke test exercises all
seven locales with fake cleanup data, confirms the cancellation boundary,
checks backup UI, and verifies that selected paths remain intact. Linux GUI
tests require DISPLAY, otherwise they are explicitly skipped. Windows cleanup
and native dialogs still require validation on Windows. `build_exe.py` must run
on Windows to produce a Windows EXE; it includes all catalogs. Install requirements-build.txt first. The builder now produces dist/CDriveCleaner.exe (one file) and dist/CDriveCleaner-Windows-x64.zip. Windows CPython under Wine can also build this PE on Linux; it does not constitute native Windows validation. Python wheel
packaging also includes the application modules and JSON data.

Cloud development: use `/usr/bin/python3` to create a virtual environment.
The default cloud Python's Tk 9 build uses core X fonts and rendered non-Latin
text invisible during inspection; the system Python's Tk 8.6 supports Xft.
Use the existing checkout; cloud tasks are already isolated and need no Git
worktree. Do not run real Windows cleanup on a Linux development machine.

Optional `CDRIVE_CLEANER_THEME=clam` uses the portable ttk theme during Wine UI tests. Without this override the default native theme is preserved.
For Wine-only font rendering failures, set `CDRIVE_CLEANER_FONT=DejaVu Sans`; native Windows keeps automatic script font selection when unset.
